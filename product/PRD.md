# PRD v0.1｜研究证据助手

**状态**：个人项目的设计与本地演示；需求尚未经过目标用户访谈验证。
**范围**：研究问题 → 公开文献来源 → 人工核对的证据卡片。
**需求来源**：[问题定义](problem-brief.md)、[访谈计划](../research/interview-guide.md)、[公开示例资料](../data/README.md)。

## 1. 用户与问题

目标用户假设为需要核对医学影像论文的研究生或科研助理。当前要解决的具体任务是：查找一项文献陈述、回到来源位置、把自己的判断与出处一起保存。真实任务频率和耗时未知，不能把产品决定写成已验证痛点。

## 2. 目标与非目标

P0 目标是展示一条可复核的路径和无答案路径。当前演示仅搜索内置、人工整理的少量公开资料；用户也可手动登记自己核对的公开论文。手动登记不是在线检索或内容验证。不执行 PDF 上传、LLM 生成、实验数字抽取或临床推断。后续是否做实验对比表、自动导入及更多文献，取决于访谈与质量评测。

## 3. 用户流程

详见[流程与异常路径](user-flow.md)。信息结构为问题输入、来源列表、证据卡片。每张卡片至少包含研究问题、人工编辑的判断、文献 ID、原文位置、资料 URL、局限和保存时间。

## 4. 需求与验收

| 优先级 | 用户故事与来源 | 可复核验收条件 |
| --- | --- | --- |
| P0 | 作为研究者，我输入一个研究问题，查看内置材料可能相关的来源。来源：产品假设。 | 输入非空问题后显示匹配的文献标题、年份、来源位置和整理摘要；空输入有提示。 |
| P0 | 作为研究者，我要核对来源后再做判断。来源：可追溯性设计。 | 每条结果有可访问的原文 URL 与章节/段落定位；界面标明“人工整理线索，需核对原文”，不把摘要伪装为自动生成答案。 |
| P0 | 作为研究者，我保存一张带出处的卡片。来源：现有证据模板及产品假设。 | 选定一条来源、填写自己的判断并勾选已核对声明后保存；卡片可再次查看、删除并导出 Markdown；导出含问题、判断、来源、DOI、定位、许可与自我声明。局限字段可选。 |
| P0 | 作为研究者，在资料中找不到证据时得到明确反馈。来源：可靠性设计。 | 未命中或越界问题显示“当前示例资料未找到”，不能保存无来源卡片，也不补写数字。 |
| P0 | 作为研究者，我已自行找到公开论文，希望用同一流程建卡。来源：内置资料覆盖有限这一已知限制。 | 任一问题下可手动登记标题、HTTPS 原文链接、具体位置及可选 DOI/许可；缺必填字段、非 HTTPS 链接或格式错误的 DOI 拒绝建卡；条目明确标记“用户手动登记、未经系统核验”，仍需勾选自我核对声明。 |
| P1 | 作为研究者，我自动导入更多公开论文并对比实验设置。来源：待验证方向。 | 待访谈和数据许可核查后细化；本阶段不实现。 |

## 5. 规则与边界

- 内置线索的文字是对来源的中文概述，不是逐字论文摘录或模型生成结论。
- 勾选已核对仅是创建者自我声明，不是独立真实性验证；不可把卡片保存量当作证据准确率。
- 来源链接应指向公开原文，卡片保留具体章节/表格定位；如果原文变更，用户须重新核对。
- 用户手动登记的标题、定位、DOI 和许可由用户提供；程序只做格式校验，不能证明原文存在、许可适用或判断受来源支持。未填写许可显示“待核实”。
- 用户输入和卡片只存于当前浏览器 `localStorage`；没有账号、云同步、权限管理或服务端。不得放患者信息、未授权全文或内部实验数据。
- 演示仅供研究工作流展示，不提供医学诊断建议。

## 6. 评测与发布门槛

按[评价方案](../evals/plan.md)建立可回答、不可回答、跨文献混淆题；人工判定出处是否支持判断。当前只运行程序验证，尚无用户成功率、质量改进或竞品比较结果。发布到公开仓库前检查链接、许可、敏感信息、可运行说明和实际状态。
